# アプリのリクエストログ停止とユーザー別ライド取得の改善

2026-10-24、`perf/app-load`。Hono の `logger` import と middleware 登録をコメントアウトし、リクエストごとの標準出力を停止した。nginx のアクセスログは引き続き alp で解析する。

## 計測

対象は s1 の Node.js 実装。変更前は `a417be7`、変更後は `5d251e7`。どちらもベンチ成功、種別エラーなし。

| 条件 | スコア |
| --- | ---: |
| 変更前（bench を SSH で直接実行） | 2115 |
| 変更後（`task bench`、ログ退避後） | 3366 |

変更前は途中で `pt-query-digest` の CPU 使用率が約80%だったことを確認した。変更後は解析処理との重複を避けた。このため同条件の比較ではなく、スコア差をログ停止だけの効果とは判断できない。ログ停止版はベンチ成功を確認した状態で、性能効果の確定には解析を重ねない条件で再比較が必要。

変更後の alp は椅子通知12,008件・平均99ms、アプリ通知10,147件・平均121ms、座標更新7,292件・平均131ms。椅子は座標更新成功まで移動しない仕様のため、座標更新の遅延削減を引き続き優先する。

`rides WHERE user_id = ? ORDER BY created_at DESC LIMIT 1` は直近ログで7,168回・約534万行走査・合計13.8秒だった。この取得を改善するため、`rides(user_id, created_at)` の複合インデックスを追加する。初期化後も反映されるよう `webapp/sql/1-schema.sql` に定義する。上記スコアはインデックス追加前の値。

型検査 `tsc --noEmit` と `git diff --check` は成功。ログを戻す場合は `main.ts` の2行のコメントを解除する。
